# Structured interpretation — phases 1 and 2

Opt in explicitly with `POST /api/plan-watch?mode=interpretation.v1` and JSON
`{"request":"Tiens-moi informé des actualités de Jannik Sinner.","language":"fr"}`.
Language may be `en`, `fr`, `mixed`, or `und`; omitted means `und`. It is a hint,
never a source-language or geographic constraint. The original request is kept
unchanged, including whitespace. Limits: 500 UTF-16 code units, one AI request,
15-second deadline, 3,000 output-token cap and bounded response/schema. The endpoint uses the existing
`OPENAI_API_KEY` and `OPENAI_MODEL` configuration. No UI calls this mode.

Successful responses have `mode`, `status` (`interpreted`, `ambiguous`, or
`unresolved`), `executable:false`, `capabilityStatus:"not_assessed"`, and an
`interpretation`. This is meaning extraction, never capability approval. No
source discovery, Watch persistence, membership resolution, matching, scheduler
or notification occurs. Legacy requests without `mode` keep their old response.

## Contracts

`src/js/watch-interpretation.js` defines strict JSON schemas and bounded runtime
validation; the adjacent `.d.ts` supplies types. All fields are required; use
empty arrays/null where appropriate. Unknown fields and enum values fail closed.
Original wording is attached by the server rather than generated by the model.

Individual subjects retain names intact. Open groups retain membership criteria;
their `members` are named examples, not an exhaustive roster. Closed groups have
explicit individual members. A bounded condition graph uses unique IDs and
AND/OR/NOT nodes or typed predicates. `news_about` takes one subject; independent
subjects use OR. `mentions_together` and `relationship` are distinct. Currency
numeric subjects are ordered base/quote; decimal amounts are strings, with
French commas normalized to dots. Only GBP/EUR canonical codes are represented
in this first version; other identification remains unresolved.

The provider returns evidence as `path`, `quote`, and nullable `context`; it never
calculates offsets. Quotes are exact copies of source text. Application code
requires exactly one occurrence, or an explicitly supplied exact unique context
containing the quote once. Missing or ambiguous spans are rejected, never guessed
or fuzzy-matched. Provider paths are restricted to subject labels, membership
objects, condition/topic/temporal/geographic/unresolved objects, and recurrence.
The returned interpretation still contains validated UTF-16 start/end offsets
with an exclusive end, calculated only by application code. Labels must be grounded;
membership, condition, topic, temporal/geographic and unresolved fields need
evidence. Validation rejects missing references, cycles, excessive depth,
unreachable conditions, obvious logical/numeric contradictions, unsupported
fields, changed numeric amounts, known comparison mismatches, and explicit
negative qualifiers that disappear. These checks do not prove complete semantic
fidelity or factual group membership. Model output remains untrusted.

Subject schema branches now distinguish individual, open-group and closed-group
shapes before decoding. A currency cannot be a group. Membership attributes are
language-neutral and separate nationality, sport and tour; bounded known lexical
equivalents normalize country codes, tennis, ATP/WTA and fashion/mode. Other
membership requirements remain explicit and unresolved. No named-person/brand
special cases or fabricated rosters are introduced.

General news wording is a domain, not a mandatory topic. A required topic cannot
duplicate a group membership value. Recurrence is unspecified unless explicitly
grounded in supported recurrence wording. Numeric "whenever/chaque fois" retains
an explicit crossing-versus-observation ambiguity rather than choosing a policy.
News predicates use null values; currency predicates use `exchange_rate`, so
localized descriptive labels cannot change those predicate identities.

Shared clauses use multiple evidence entries with the same condition path:
quote the shared phrase separately from each entity name. Separate fragments
are never concatenated into a fabricated quote. Shared spans may be reused, but
each news/co-occurrence/relationship predicate needs evidence for its own
referenced subjects. Existing uniqueness and context rules remain enforced.

News intent and news predicates require `media_news`, regardless of entity type.
`official_company` requires event/change intent and a canonical source-qualified
event (`official_company_announcement`, `official_registry_filing`, or
`official_registration_change`) grounded in an explicit official-source clause.
Other source requirements remain unresolved; this does not add capabilities.
Contradictions fail with safe reasons `DOMAIN_PREDICATE_CONFLICT`,
`CONDITION_EVIDENCE_MISMATCH`, or `OFFICIAL_SOURCE_UNGROUNDED`; the opt-in HTTP
response exposes those reasons without raw model payloads or source text.

`MonitoringPlanV1` retains the `not_assessed` placeholder and now also defines a
non-executing supported plan. Phase 3's isolated assessor/compiler is documented
in [structured-capabilities-v1.md](structured-capabilities-v1.md); no creation or
execution integration exists.

## Failures and compatibility

Errors are sanitized: `INVALID_INTERPRETATION_REQUEST` (400),
`INTERPRETATION_FAILED` (502), `AI_SERVICE_UNAVAILABLE` (503), and `AI_TIMEOUT`
(504). No fallback query, implicit clarification call, or retry occurs. An
ambiguity is a successful extraction needing clarification, not a provider error.

Provider transport is shared with the existing clarification service; its
legacy prompt, schema, model fallback, response contract and currency shortcut
are retained. No existing Watch is reinterpreted. No changes are made to parser,
currency evaluation, aliases, saved definitions/queries, databases, auth,
baselines, ledgers or notifications. Opt-in output cannot be used directly by
current persistence. Phase 4 requires separately approved creation and
version-aware persistence work.
